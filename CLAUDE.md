# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

A reference site for the OpenSubtitles Hash (OSHash) algorithm with verified implementations in 49 languages. Hosted at opensubtitles.github.io/oshash via GitHub Pages. Dev server runs on port 3005.

Most implementations run on host toolchains. Eight (Ada, COBOL, Forth, Objective-C, Prolog, Scheme, Smalltalk, Standard ML) are built inside a throwaway Docker image — see "Docker-built languages" below.

The OSHash algorithm: `hash = file_size + sum_uint64_le(first_64KB) + sum_uint64_le(last_64KB)` — unsigned 64-bit wrapping addition over little-endian uint64 values.

## Commands

```bash
# Dev server with live reload (watches public/ for changes)
node server.js --dev

# Run the full test suite (compiles + runs all 49 implementations)
bash test_all.sh

# Test a single implementation
python3 implementations/python/oshash.py test-data/testfile.bin
# Expected: e7e2e71e035b137f
```

## Architecture

- **`server.js`** — Node.js HTTP server (port 3005). Serves `public/` static files, `/api/source/{lang}` for implementation source code, `/test-results.json` for test data. In `--dev` mode, injects SSE live-reload script and watches `public/` via chokidar.
- **`public/`** — Frontend: `index.html`, `style.css`, `app.js`. Single-page, no framework. `app.js` defines the LANGUAGES array and renders implementation cards with lazy-loaded source + copy-to-clipboard.
- **`implementations/{lang}/`** — One directory per language, each containing a standalone CLI program that takes a file path and prints the 16-char hex hash to stdout.
- **`test_all.sh`** — Master test runner. Compiles (if needed) and runs each implementation against two test files, compares output to reference hashes, writes `test-results.json`.
- **`test-data/`** — Deterministic test files generated by `generate_testfile.py`. `testfile.bin` (1MB) and `testfile_small.bin` (128KB edge case).
- **`public/downloads/`** — Original OpenSubtitles test files: `breakdance.avi` (12.9MB, hash `8e245d9679d31e12`) and `dummy.rar`.

## Adding a New Language

1. Create `implementations/{lang}/oshash.{ext}` — must accept a file path as CLI arg, print 16-char lowercase hex hash to stdout.
2. Add build/run entry in `test_all.sh` (follow existing `run_test` pattern).
3. Add source file mapping in `server.js` `fileMap` object.
4. Add entry to `LANGUAGES` array in `public/app.js`.
5. Run `bash test_all.sh` to verify.

## Docker-built languages (Ada, COBOL, Forth, Objective-C, Prolog, Scheme, Smalltalk, Standard ML)

Toolchains we don't keep on the host are built inside a throwaway image
(`tools/Dockerfile.builder`, Ubuntu 22.04 so binaries are glibc-compatible).
`tools/build_docker_langs.sh` produces a host-runnable artifact for each:
- Ada, Objective-C — statically linked native binaries.
- Prolog (GNU Prolog) — native binary (links only libc/libm).
- Scheme (Gambit), Standard ML (Poly/ML), COBOL (GnuCOBOL) — native binary with
  their runtime `.so`s bundled beside it via an `$ORIGIN` rpath.
- Forth (gforth), Smalltalk (GNU Smalltalk) — the VM binary + its image
  (`gforth.fi` / `gst.im`) are bundled; the run command points at them.

Pass `--rmi` to delete the image and reclaim `/var` afterwards (the artifacts
persist). All built artifacts are gitignored; `test_all.sh` runs them if present
and SKIPs them otherwise, so on a fresh clone run the build script first.

Gotchas worked around: Gambit, Poly/ML and GNU Prolog truncate/​break file seeks
past 2^32, so Scheme, Standard ML, COBOL and Prolog read the trailing 64 KB via
`tail -c` (like the Bash/AWK ports). COBOL uses `COMP-5` 8-byte fields (native
little-endian, full 64-bit range) for the uint64 wrap; Prolog keeps the hash as
four 16-bit words (its integers are tag-limited). Objective-C uses the GNU
runtime's `Object` root class (no Foundation).

## Non-Standard Runtime Paths

Many runtimes are installed to `/home/claude/local/` (not in default PATH) due to `/usr` partition constraints. `test_all.sh` prepends these to PATH:
`/home/claude/local/go/bin`, `/home/claude/.cargo/bin`, `/home/claude/local/nim/bin`, `/home/claude/local/dart-sdk/bin`, `/home/claude/local/kotlinc/bin`, `/home/claude/local/pwsh`

## Key Pitfall

The CSS/JS is served through Cloudflare. When updating styles or scripts, bump the `?v=N` cache-buster in `index.html` link/script tags, otherwise Cloudflare may serve stale cached versions (including cached 404s).
